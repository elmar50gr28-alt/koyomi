# 宿曜・日家九星と計算条件

## 変更の範囲

日付を単純に27で割る宿曜と、日付を9で割る日盤を廃止した。既存の占術別文章・象意辞書は再利用し、本命宿・相性分類・日盤の計算結果を接続する。新しい処理は `src/shared/traditional-calendar-core.js`、条件の評価は `src/reading/calculation-readiness.js` に置く。

## 宿曜

- 端末内の Astronomy Engine で朔と中気を求め、日本時間の暦日で月を区切る。入力された生年月日は、その暦日を日本時間の暦表へ当てはめる。出生地のUTC時刻から別の日付へ変換する方式ではない。
- 冬至を含む月を11月とする。次の冬至月まで13か月ある場合、11月の次から最初の中気のない月を閏月とする。
- **冬至優先方式であり、すべての時代の天保暦を完全再現するとの主張はしない。** 二至二分を含む月の配当が条件と一致しない周期は `calendarDifference` と注記で示す。影響する冬の周期にも注記を引き継ぐ。
- 2033〜2034年は閏11月案を採用し、方式差を表示する。国立天文台は複数案を説明しており、唯一の公式旧暦と表示しない。
- 旧暦月初の二十七宿表を用い、閏月は同名の本月と同じ起点を採用する。相性は命・栄・衰・安・危・成・壊・友・親、業・胎の三九の法で分類する。
- 対応する入力年は1900〜2200年。範囲外や天文エンジンが使えない場合は判定保留にし、旧来の簡易周期で穴埋めしない。

## 日家九星

- 日本時間の夏至・冬至に最も近い甲子を転遁日とする。干支の前半30日は直前、後半30日は直後の甲子を採る。
- 通常180日、240日になる間隔は後半60日を30日ずつに分ける置閏を採用。途中の反転で同じ三碧または七赤を続ける。
- 「こよみのページ」作者の公開計算方針に対応する方式を採用している。同資料自身が方式差を説明しているため、他流派の暦と必ず一致するとは表示しない。
- 年家九星の立春による年区切りは既存計算を維持し、星の名称を正しい一白水星〜九紫火星で表示する。日家九星の変更は、九星全体系や方位盤を全面実装したことを意味しない。

## 表示と重み

従来の固定的な「確度68」「確度72」や、質問文字数でタロット・ルーンの確度を上げる処理を廃止した。「入力・計算条件」として、暦換算の実行、方式差、出生時刻・座標、姓名辞書などの条件と制約を示す。タロット・ルーンは「象徴補助」、六星周期は「独自参考」とする。

数値 `score` は既存の統合重みとの互換用の内部指標で、実測一致率や的中確率ではない。新しい `kind` と `predictiveAccuracy: null` で区別し、通常画面の確率に見えるパーセント表示は外す。四柱のルールに付属する別のconfidenceは「根拠確認の目安 …/100（的中率ではありません）」と表示する。元の保存データやAPIの数値は書き換えない。

計算根拠の変更後に古い日次結果を再利用しないよう、日次エンジンは3.14.0へ更新する。過去のキャッシュを一括削除せず、新しい生成ではバージョンを含むキーを用いる。

## 検証

`npm run test:traditional-calendar`：国立天文台公開日付12例、2024〜2026年の宿配当1,096日、27×27の相性、1900〜2100年の日家九星73,414日と18回の置閏反転を検査する。旧暦は同期間の各月の初日・末日も検査する。2026年の公開転遁日と一致すること、2033年問題の注記、日付のタイムゾーン独立性、計算不能時の保留、実際のアプリ接続を確認する。

長期走査は不変条件の検査で、全日程を外部の暦表と照合したものではない。天文計算と流派の整合性を改善するもので、未来の的中率向上を検証したものではない。
