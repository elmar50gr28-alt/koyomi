# 奇門遁甲の典拠・レビュー台帳

`data/qimen/review-register.json` は現行実装を追跡する未承認の作業台帳です。アプリには読み込ませません。登録件数は正確性・完成率を示しません。

## 初期状態

- 出典と参照盤は未登録です。書名・版・巻頁を確認できるまで空配列を保持します。
- 流派は現行コードの選択肢を候補として記録しています。正式採用の決定ではありません。
- 全ルールは `needs_source_review`、確度は `null` です。未確認をゼロ確率や低確度と混同しません。
- 評価係数は実装上の内部スコアであり、成功確率として承認しません。

## 資料の登録条件

`sources` の各項目に `sourceId`、書名、著者、版・刊年、所蔵先または検証可能なURL、巻頁・章節、対象流派、権利状態、確認者・確認日を記録します。原文・要約・現代解釈・AI生成文を区別し、現代書籍の本文や翻訳を無断転載しません。書誌だけの登録は規則の承認を意味しません。

## ルールとレビュー

`ruleId` を維持し、該当する `sourceIds` と巻頁を照合します。流派間で相反する規則を上書き統一せず、流派ごとの項目へ分離します。`confidence` は根拠と評価基準が確認されるまで `null` にします。

レビュー状態の運用:

1. `needs_source_review`: 典拠確認前。
2. `needs_human_review`: 典拠・対象流派・参照例を登録し、人間の採否確認を待つ。
3. `approved`: 人間の確認者・確認日・採用理由を記録し、典拠と参照盤の検証が揃った項目のみ。
4. `rejected`: 不採用理由を残して保持する。

台帳を読む将来のエンジンは、状態不明・未登録・未承認を承認済み扱いにしません。未知フィールドを保持し、個人の出生情報や保存済み人物データは台帳に含めません。

## 参照盤の登録条件

`referenceCases` に `caseId`、典拠と巻頁、日時、IANA時区、緯度経度、時刻基準、日境界、流派、期待局数・全九宮・旬首・値符・値使、確認者を記録します。日時・地点は公開例または架空のテスト用とし、現行コードが出した盤をそのまま正解として登録しません。

節入り前後、23時・0時、陰陽遁の切替、六旬、甲時、中宮を含む例を優先します。端末時区を変えた検証も行います。

## 次工程

確認可能な典拠を登録し、参照盤と照合してからAPI抽出へ進みます。未確認の書名や盤を推測して登録しません。監査の詳細は `docs/QIMEN_FIELD_AUDIT.md` を参照してください。
