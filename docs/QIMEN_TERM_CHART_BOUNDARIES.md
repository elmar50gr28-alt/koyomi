# 奇門遁甲・節入り前後の盤切替監査

確認日: 2026-10-03
対象main: 34f0cd582ce739ca72e21184179969a49187cec7

## 方法と対象

同梱Astronomy Engine 2.1.19と実画面の後段の太陽黄経再定義、既存の `qmdjChart` をNode VMで実行する。ファイルのSHA-256を照合し、近似式へのフォールバックが0件であることを確認する。アプリの計算式や局数表は変更しない。

`data/qimen/naoj-solar-terms-2025.json`、2026年・2027年の同名資料の二十四節気72件を使う。各公表時刻の1日後から計算した節入りを探索し、その前後1秒の盤を比較する。公表値は分単位のため、公表時刻そのものを秒単位の境界とは扱わず、別途前後90秒で前節気・当該節気の選択を確認する。この90秒は今回の標本用の回帰検出幅である。

標準時UTC+9、経度135度、23時日境界、拆補法（chaibu）と節気三元固定式（fixed）の2方式が対象。144組について節気名、陰陽遁、局数表と三元の接続、九宮と地盤の9要素、夏至・冬至の陰陽遁切替、固定式の上元への復帰を検証する。地盤・九宮は前後の構造化結果を比較し、日時や説明文の差で変更と数えない。

## 補正方式を組み合わせた追加監査

2026年の24節気を、経度135度・東京139.7671度・那覇127.68度、standard / local / solar、2方式、UTC+9・23時日境界で確認した。追加432組。天文計算で得た節入りの瞬間を固定し、既存の時刻補正後の日時がその瞬間に達する入力時刻を二分探索した。入力切替の前後1秒で前節気・当該節気、局数と三元の接続、九宮9要素、固定式上元への復帰を確認した。既存3年144組の試験も維持する。

| 地点 | 時刻方式 | 入力切替 − 天文節入り（分、最小〜最大） |
| --- | --- | --- |
| 経度135度 | standard | 0 |
| 経度135度 | local | 0 |
| 経度135度 | solar | -16.183 〜 +14.368 |
| 東京 | standard | 0 |
| 東京 | local | -19.068 |
| 東京 | solar | -35.251 〜 -4.699 |
| 那覇 | standard | 0 |
| 那覇 | local | +29.280 |
| 那覇 | solar | +13.095 〜 +43.647 |

符号が負なら入力時刻上の切替が天文節入りより早く、正なら遅い。表示の小数は実装の測定結果であり、均時差近似式の精度保証ではない。均時差は切替時刻に依存するため、solarは定数を引くだけではなく実装の補正を再評価して解いた。

追加432組すべてで、その入力切替の前後に地盤・九宮が変わった。一方、未補正の天文節入りの前後1秒で節気が切り替わるのは192組（standardの144組と経度135度のlocalの48組）。残る240組は補正により切替が移動した。フォールバックは0件。端末時区Asia/TokyoとAmerica/New_Yorkで同じ集計だった。

### 仕様上の未確定点

現在の `qmdjChart` は `qmdjAdjustedTime` の結果を `qmdjTermStart` に渡す。つまり天文計算に渡すUTC瞬間まで補正されるため、太陽の計算精度とは別に上記の移動が発生する。今回の試験はこの現行挙動を記録するものであり、移動を正しい仕様として承認するものではない。

節入りを入力の実瞬間で判定する方針と、補正した時刻表示に対して節入りの境界をどう表現するかを分ける必要がある。資料・時刻基準を確認し、天文判定と日・時柱・符頭用の補正の分離を検討する。全地点・時区・0時日境界や古典の正否は今回も保証しない。アプリの計算式と審査状態は変更していない。

## 限界と次工程

これは現在の実装の切替と整合性を確認する回帰試験であり、古典の日時付き参照盤との照合や流派規則の承認ではない。公式暦の分単位の丸め区間、全年度・全地点・地方平均時・真太陽時・0時日境界はこの試験だけでは保証しない。画面での通信失敗も対象外である。既存の禁止事項・安全ルール・資料と候補の審査状態を保持する。

天文資料と既存仕様を確認し、実瞬間での天文判定と暦・日・時柱用の時刻補正を分ける [方針案](QIMEN_TIME_BASIS_POLICY.md) を作成した。次は提案の採否を明示したうえで、補助関数と最小接続を実装し、境界と他占術への影響を検証する。流派・参照盤の審査は別に継続する。
